# v0.9 Single-Function Corpus — Temporal-Freeze Verification

Phase: 9.5d corpus-wide temporal-freeze verification. Read-only proof over git history
and the authoritative dataset. No case, engine, scoring, or data was changed; this report
is the only new artifact.

## What this proves

Every one of the 30 single-function cases was committed to git BEFORE any run of that case
was produced, and the exact content that was committed is byte-identical to the content that
was actually scored. No case could have been selected, altered, or re-authored after its
Darwin performance was known.

Three independent facts establish this per case:

1. ORDERING. The freeze commit of the case content (committer timestamp, UTC) precedes the
   earliest authoritative run of that case (UTC).
2. ANCESTRY. The freeze commit is an ancestor of (or equal to) the dataset's frozen
   `git_head` `8b2dd60`, so the content was already committed at the point the run was taken.
3. CONTENT IDENTITY. The case `original.py` committed at `git_head` is byte-identical
   (sha256) to the `gen_00_original.py` actually fed to Darwin in every run; the committed
   baseline metrics and reference floor match the run's recorded baseline and the dataset's
   per-metric floor. The thing that was frozen is the thing that was scored.

## Method

For each case id in the dataset:

- FREEZE COMMIT = the last commit reachable from `git_head` 8b2dd60 that modified
  `cases/<id>/` (`reference`/`original`/`golden`/`baseline`). For re-authored cases this
  correctly resolves to the commit of the version that produced the authoritative runs, not
  an earlier superseded version.
- EARLIEST RUN = the minimum run-dir timestamp across the case's 5 authoritative runs.
- VERDICT = PASS iff freeze_ts < earliest_run_ts AND freeze commit is an ancestor-or-equal
  of 8b2dd60 AND committed `original.py` is byte-identical to every run's `gen_00_original.py`.
