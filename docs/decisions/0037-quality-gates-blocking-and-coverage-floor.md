# 0037 Quality gates driven to zero and flipped to blocking; coverage floor at measured-minus-2

Decision: The quality gates are driven to zero findings and flipped from advisory to blocking, and a coverage floor is added to the test job. The four tool gates -- ruff lint (`ruff check tools/`), ruff format (`ruff format --check tools/`), mypy (`mypy tools/`), and the gitleaks secret scan -- plus the pip-audit dependency vulnerability scan now fail their job on any finding, blocking the merge. The test job gains `--cov-fail-under=56`, set from production coverage measured at 58 percent less a 2-point margin.

Context: The quality tooling shipped advisory-first in M0 (decision 0016): halting work on a several-thousand-line untyped, never-linted codebase on day one would have been wrong, so the gates surfaced findings without blocking while the baseline was driven down. By v0.7 the baseline was ready to enforce. P7.3 cleared all three code gates to zero in three isolated commits (`ruff format` mechanical pass; the root lint findings fixed not suppressed, no `noqa` and no per-file ignore; the two missing `_results` annotations for a clean mypy), recorded in `docs/quality-baseline.md`. The pip-audit finding (CVE-2025-71176) was cleared by the pytest 9 bump first (decision 0036), so the vulnerability scan flips to blocking against a clean closure rather than on a live finding. gitleaks is included in the flip: it scans the full commit history for secrets and had no findings, so it joins the other gates as blocking with no baseline to clear. With every gate at zero, P7.4 flipped all of them to blocking; a finding now fails its job.

Coverage floor policy (measured-minus-2): coverage was reported but not gated before P7.4 (no `--cov-fail-under`). Production coverage, measured by the exact CI invocation from `tools/` with the `--cov-config` omit that excludes the test files, is 58 percent. The gate is set 2 points below that, at 56, as a cross-version and CI margin: the suite runs on three host Pythons (decision 0038) and small per-interpreter coverage differences must not flip the gate red on an unrelated leg. The floor is deliberately set from the measured number rather than an aspirational target, so the gate enforces what the suite actually covers, not a goal it does not meet. The floor is honest only because the `--cov-config` omit excludes test files: counting the test files (which are near-fully executed) would inflate the percentage and make the gate trivial; a CI comment on the suite step records exactly this.

Alternatives rejected:
- Flip the gates to blocking without first driving findings to zero: rejected. A gate that goes blocking on a known nonzero baseline blocks every merge on pre-existing debt; the discipline (decision 0016) was to drive to zero first, then enforce.
- Set the coverage floor at the measured 58 (or higher, as a target): rejected. 58 leaves no margin: a single uncovered line on one matrix leg, or a small cross-version difference, would fail the gate on otherwise-passing code. A target above 58 would gate on coverage the suite does not currently have, blocking merges on aspiration. Measured-minus-2 enforces reality with a thin, honest margin.
- Drop `--cov-config` (count everything, including test files) to reach a higher number: rejected. The test files are near-fully executed, so including them inflates the percentage and measures nothing about production coverage. The omit is what makes the floor meaningful.
- Leave pip-audit or gitleaks advisory while flipping ruff and mypy: rejected. A partial flip leaves a secret leak or a dependency CVE merge-able, which is exactly what those gates exist to stop. The CVE was cleared first (decision 0036) so the full set flips together on a clean baseline.

Consequences: ruff lint, ruff format, mypy, gitleaks, and pip-audit are blocking; a finding in any of them fails CI and blocks the merge. The test job fails if production coverage drops below 56 percent. `docs/quality-baseline.md` records the zero state, the blocking flip, and the floor. The `--cov-fail-under` value and the `--cov-config` omit are unchanged after this phase sets them; the value stays 56. No source, test, scoring, generation, or evaluation logic changed; this phase changed gate enforcement and added a coverage threshold, not behavior.
