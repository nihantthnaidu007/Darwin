# 0026 v0.5 release: bump to 0.5.0

Decision: The v0.5 milestone (correctness, determinism, and reproducibility) is released as 0.5.0. The version moves from 0.4.1 to 0.5.0 in pyproject.toml; the README release lines and CHANGELOG are updated to 0.5.0; and 0.5.0 is tagged at its merge commit on main, after the merge and the post-merge audit. The release stays in the 0.x line: the open boundaries from decision 0005 (most prominently the in-process verdict-forgery residual, decision 0008) are not yet closed, so this is not a 1.0. No optimization, scoring, or equivalence behavior changed in v0.5; the milestone hardened correctness, configuration, concurrency safety, and the oracle-sanitization contract, and built reproducibility machinery.

Context: v0.5 set out to close four findings. Three are closed in full. C1 (feedback materiality): `feedback_load_bearing` was true whenever any case used a later generation, contradicting the prose that the loop is not load-bearing on this corpus; it is redefined with a documented materiality threshold (a later-generation gain must exceed 0.5 percentage points), and reports/aggregate.json was regenerated so the machine-readable artifact agrees with the prose (decision 0021). D1 (concurrency-safe evaluator state): the dynamic-import module names that the evaluation path minted from module-global counters (a non-atomic read-modify-write that could collide on a sys.modules name) are now minted from uuid across all three eval-path loaders (mverify, validate_mcase, mdiffer), the container path is confirmed concurrency-safe by unique names and fresh temp dirs, and production evaluation remains sequential (decision 0024). N2 (oracle-sanitization contract): the witness prefixes that the producer (mevaluator) emits and the sanitizer (mloop) strips are bound to a shared marker so a wording change cannot silently expose the oracle, with a real-producer oracle-leak test as the standing guarantee (decision 0025). F1 (determinism and reproducibility) is closed on two of its three parts and deferred on the third, stated plainly below.

F1's deferred half: F1 is closed on configuration and determinism (temperature pinned explicitly to 1.0 with full run provenance recorded in run.json, decision 0022) and on the reproducibility machinery (a variance harness with committed-snapshot persistence that derives the variance table from snapshots, decision 0023). The artifact-backed regeneration of the multi-file variance dataset (P5.3b) is NOT done in v0.5: it requires an authorized model-spend run to populate reports/variance_runs/ with real snapshots, and it is parked on that authorization. Until it runs, reports/mvariance.json remains the 2026-06-13 hand-recorded dataset, and its note says so honestly. The machinery to make the regeneration reproducible exists and is tested on synthetic snapshots; only the paid run is outstanding.

Alternatives rejected:
- Release as 1.0 or leave the 0.x line: rejected. The open boundaries from decision 0005 are unchanged in v0.5; a 1.0 would falsely signal a stable, production-grade, forgery-proof release. The 0.x rationale stands.
- Hold the release until P5.3b runs: rejected. C1, D1, and N2 are fully closed and F1's configuration and machinery are delivered; that is a coherent, shippable milestone. Blocking the release on a paid run that is parked on authorization would withhold delivered, audited work for a single deferred regeneration that is already documented as deferred.
- Bump only the patch (0.4.2): rejected. v0.5 closes four distinct findings across correctness, determinism, concurrency, and the safety-critical oracle contract, plus new reproducibility machinery; a minor bump (0.5.0) is the honest signal, parallel to how v0.4 was a minor bump over 0.3.0.

Consequences: The current release is 0.5.0, tagged at its merge commit on main after the post-merge audit, in one-to-one correspondence with the release (the clean pattern decision 0020 prescribed for 0.5.0). The prior release 0.4.1 and the void v0.4.0 tag are unchanged (decisions 0019, 0020); 0.4.1 references in CHANGELOG, the decision records, and CONTEXT history remain as intentional history. The release stays 0.x per decision 0005. P5.3b is the one carried-forward piece of v0.5, parked on authorization; when that run completes, `python variance_harness.py run` then `derive` regenerates reports/mvariance.json from committed snapshots and supersedes the hand-recorded dataset. The next milestone is v0.6 (supply-chain): digest pinning, a lockfile with hashes, and the verdict-emission seam.
