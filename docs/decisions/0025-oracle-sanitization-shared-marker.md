# 0025 Oracle-sanitization contract bound to one shared marker

Decision: The oracle-bearing witness-line prefixes are defined once, in tools/oracle_markers.py, as ORIGINAL_OUTCOME_PREFIX = "original :" and CANDIDATE_OUTCOME_PREFIX = "candidate:". mevaluator (the producer) emits the equivalence-divergence witness's two outcome lines with these prefixes, and mloop (the sanitizer) strips exactly those lines by the same prefixes before any feedback reaches the generator. Both files import the constants from oracle_markers, which imports nothing from either, so there is no circular import and the literal strings exist in exactly one place. The real-producer oracle-leak test (tools/test_oracle_leak.py) is the standing guarantee: it builds a rejection through the real mevaluator producer with a distinctive sentinel where the oracle would be, in a real MEvaluation carrying the gate and reason_code mevaluator actually sets, runs it through the real mloop.format_feedback, and asserts the sentinel never survives, while the diverging INPUT that Fork 1 permits still does. The sanitized feedback to the generator is semantically unchanged from before; only the coupling mechanism changed.

Context: N2 identified that mloop stripped the oracle from feedback by matching mevaluator's exact output strings ("original :" and "candidate:"), a literal coupling duplicated in two files. A wording change to mevaluator's witness format would silently defeat the strip and expose the answer key to the generator, breaking Fork 3 (decision 0012, the candidate must never see the oracle). Binding the producer and the sanitizer to one shared marker removes the duplication: there is now a single string to change, and both sides move together. The guarantee was shown to bite: temporarily drifting the producer's original-outcome prefix off the shared constant (emitting `orig=>` instead) makes the equivalence-vector leak test fail, because the sanitizer still strips the shared `original :` and the sentinel outcome leaks through. That demonstrates the test is a real guard, not a tautology. Because the leak tests drive the real producer and the real routing end to end, they catch a leak from any cause: a producer prefix change, a routing-key drift that misroutes the rejection, or a witness-format change.

Alternatives rejected:
- Restructure the feedback into structured fields (oracle-bearing fields the sanitizer drops by key, instead of formatted strings parsed by prefix): rejected for this phase as a deeper redesign, out of scope. It is the strongest long-term option and is noted here as a future direction; the current change is the minimal one that removes the silent-drift hazard.
- Define the prefixes inside mevaluator and import them into mloop: workable (mloop already imports mevaluator, and mevaluator does not import mloop, so no cycle), but a dedicated oracle_markers module makes the shared contract explicit, lets both producer and sanitizer import from a neutral home rather than one depending on the other for a safety-critical constant, and reads as the single source it is.

Consequences: The oracle-sanitization contract for generator feedback has one literal home (oracle_markers.py); mevaluator.py and mloop.py carry no copy of the prefix literal. The standing guard is test_oracle_leak.py, complemented by the existing FLAG 1 sanitization matrix in test_mloop.py. Honest residual: the routing keys the sanitizer branches on are not all shared. The reason codes are (TESTS_FAILED is imported from verify_case by both producer and sanitizer; NON_EQUIVALENT lives in mevaluator), but the verdict string values ("scored", "rejected") and the gate string values ("equivalence", "tests") are still bare literals duplicated across producer and sanitizer. They are now guarded by the leak test, which fails if their drift causes a misroute (a misrouted equivalence rejection would skip the equivalence strip and leak the witness outcome, failing the test). Sharing those routing keys the same way is a recommended follow-up, not done here. The container path, the equivalence comparison, the metric basket, generation, and what the feedback says or how gates score are all unchanged; decision 0012 stands. Two human-facing prints of a witness that also use an `original :` format -- mverify's operator stderr log and validate_mcase's validator output -- are off the generator-feedback path (the operator and the case-soundness validator are trusted, not the candidate) and out of scope for this phase; they are not part of this contract.
