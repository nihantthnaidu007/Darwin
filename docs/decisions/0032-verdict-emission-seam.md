# 0032 The verdict-emission seam (typed VerdictEmitter, in-process default)

Decision: Introduce a typed `VerdictEmitter` seam between the multi-file loop and the verdict producer, ship exactly one implementation (`InProcessEmitter`, the 1.0 default), make the verdict (`MEvaluation`) serializable, and retype the consumers to the interface, so the 2.0 out-of-process emitter swaps in by replacing ONE component without touching any consumer. This changes NO 1.0 behavior: the default path stays in-process and byte-identical.

What was built:
- `tools/verdict_emitter.py`: a `typing.Protocol` `VerdictEmitter` with a single method `emit(case_dir, candidate_dir, timeout) -> MEvaluation`, and exactly one concrete implementation `InProcessEmitter`, whose `emit` delegates to `mevaluator.evaluate`. It wraps `evaluate()`; it reimplements no gate, scoring, or equivalence logic, so the verdict logic lives in exactly one place. The Protocol is `runtime_checkable` so a consumer or test can assert an object satisfies the seam.
- `mevaluator.MEvaluation.to_dict` / `from_dict`: one lossless serialization of a verdict, round-tripping both the scored and the rejected shape including the None fields, JSON-ready (no custom encoder). `mevaluator.main()` was refactored to serialize via `to_dict` rather than its prior ad-hoc dict, so there is a single serialization used in one place and ready for the boundary.
- `mloop.run_loop` and `mbenchmark.run_benchmark` were retyped to the seam. `run_loop` takes an `emitter` (a `VerdictEmitter`) and produces every verdict through `emitter.emit(...)` instead of calling `evaluate()` directly; `run_benchmark` takes an `emitter` and threads it to the loop. The defaults make behavior byte-identical to before; a 2.0 emitter is injected by passing a different instance.

Typed seam over a minimal documented seam, deliberately: A1's forward-compat half could have been closed with prose alone (a note that "a future version will move the evaluator out of process"). The typed seam was chosen instead as a deliberate forward-commitment to 2.0: it makes the swap point a real, type-checked landmark in the code with a test that proves an alternate implementation drives the loop unchanged, rather than an aspiration that the next author has to discover and design from scratch. The cost is one small module and a retyped parameter on two functions; the benefit is that the 2.0 out-of-process emitter is a drop-in, and the seam cannot silently rot because the suite exercises it.

One protocol, one implementation, no more: no registry, factory, plugin system, config-driven emitter selection, second shipped implementation, or out-of-process implementation is built here. The out-of-process emitter is RECEIVED in 2.0; it is not built now. The ONLY non-in-process emitter that exists is the test fake in `tools/test_verdict_emitter.py`, which is test code and is never shipped. There is no CLI flag or environment variable to select an emitter (that would be config-driven selection, explicitly out of scope); the seam is a function parameter, injected programmatically.

The serializable verdict is the boundary payload: an out-of-process emitter must return the verdict across a process boundary, so `MEvaluation` carries its own lossless `to_dict`/`from_dict`. `main()` uses the same `to_dict`, so the boundary shape is exercised by the existing CLI and there is a single source of it rather than two drifting serializations (the prior `main()` dict was ad-hoc and partial: it dropped `feedback` and the full `metrics`, and added a derived `aggregate`). `from_dict(to_dict(e)) == e` is asserted for both shapes, including across a real `json.dumps`/`loads` hop.

Preserving the existing in-process test seam: `run_loop` already had an injectable `evaluate=mevaluator.evaluate` callable used by the offline loop tests (no API key, no Docker). That parameter is kept, and the default emitter is `InProcessEmitter(evaluate)`, so the existing tests that inject `evaluate=<fake>` are byte-identical and unchanged; `evaluate` now configures the default emitter's in-process delegate and is ignored when an `emitter` is passed. `run_benchmark` forwards `emitter` to `run_loop` only when one is set, so an injected fake `run_loop` with the historical four-argument signature keeps working untouched. This keeps the suite count unchanged except for the new seam tests, and adds no second implementation: every `InProcessEmitter` instance is still the in-process emitter calling whatever in-process `evaluate` it was handed.

The single-function legacy path is out of scope: `evaluator.py` (`Evaluation`) and `loop.py` are the legacy single-file system; the production path is multi-file (`mevaluator`/`mloop`/`mbenchmark`), and only it is retyped. The single-function path is untouched.

A1 open by design at 1.0: the in-process default is acceptable under the single-user-trusted posture because forging one's own optimization verdict is pointless (you have no incentive to cheat your own simplifier; the reward-hack audits found zero forgery signatures). A multi-tenant 2.0, where a forged pass is rewarded, requires the out-of-process emitter for forgery resistance. Until then, A1 in-process verdict forgery (the frame-locals serializer hijack and compute-and-lie) is open by design, pinned as the two decision-0008 `xfail` vectors in `tools/test_behavior_gate_limits.py`. The seam is exactly the prepared swap point for the process split that closes the hijack vector in 2.0 (compute-and-lie remains even then, as decision 0008 notes). SECURITY.md documents this posture and names `VerdictEmitter` as the single 2.0 swap point.

Scope note on numbering: this is decision 0032; 0031 is reserved for the sibling P6.4 sub-phase (the defense-in-depth flags), which is out of scope here.

Consequences: The production loop and benchmark now produce verdicts through a typed `VerdictEmitter`, with `InProcessEmitter` the byte-identical 1.0 default and the verdict serializable as the boundary payload. The 2.0 out-of-process emitter is a one-component replacement that touches no consumer, and a test fake proves the swap drives the loop unchanged. No gate, scoring, equivalence, sandbox-lockdown, feedback-sanitization, or generation logic changed; `evaluate()`'s behavior and `format_feedback` are unchanged; the single-function path is untouched. The only behavioral change anywhere is `mevaluator.main()`'s logged serialization shape, which now uses `to_dict` by design.
